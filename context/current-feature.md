## Goals

<!-- Goals & requirements -->

- Add `src/lib/db/items.ts` with the data-fetching functions the dashboard needs (pinned items, recent items, and the item counts for the stats cards).
- Fetch items directly in the `/dashboard` server component — no API route, no client fetching. It is already `async` and resolves the user through `getCurrentUserId()`.
- Derive each item card's icon and left border color from its item type, the same way `CollectionCard` does through the `--type-color` variable.
- Keep everything the card renders today: type icon badge, title, description, pin and favorite markers, tags and the updated date. Reference `context/screenshots/dashboard-ui-main.png`.
- Hide the "Pinned" section entirely when there are no pinned items (no empty state there), while "Items" keeps its empty message.
- Update the stats cards so Items and Favorite items come from the database — the collection numbers already do.
- Verify in the browser against the seeded demo data, then `npm run build` and `npx tsc --noEmit`.

## Notes

<!-- Any extra notes -->

- Spec: `context/features/dashboard-items-spec.md`
- **Follow the collections pass.** `src/lib/db/collections.ts`, `src/lib/db/user.ts` and `src/types/collection.ts` set the pattern for this one — user-scoped queries, a DB-shaped view type, and no N+1. Match it rather than inventing a second style.
- **No auth yet.** Keep using `getCurrentUserId()` from `src/lib/db/user.ts` — still the single call site to swap for `auth()` at milestone 1.
- **Types.** `ItemCard` is typed against `MockItem` and calls `getItemTypeById` from `src/lib/mock-data.ts`. It needs a DB-shaped type (`src/types/item.ts`) carrying its own item type, so the lookup goes away. `TypeIconBadge` already takes the shared `ItemTypeBadge`, so it should not need to change.
- **Shape mismatches to resolve:** `description` is nullable in the schema but the card renders it as a string; `updatedAt` is a `Date`, not the ISO string the card formats and passes to `dateTime`; and `tags` is a relation, so it needs selecting and mapping to names.
- **Avoid the N+1 on item types.** Include the item type with each item in the query (a Prisma `include`/`select` on the relation) rather than a lookup per card.
- Two queries where one would do: pinned and recent are different orderings, but the stats counts are cheap `count` calls. Use `Promise.all`, as the page already does.
- **Ordering.** Recent items are `updatedAt` desc, limit 10 (`RECENT_ITEMS_LIMIT`). `lastUsedAt` powers "Recently used" elsewhere in the spec and is not what this section shows.
- The sidebar's per-type item counts and collections list still come from `src/lib/mock-data.ts` and are out of scope — the spec is about the main area. Leave the mock data file in place; do not delete it while the sidebar still imports it.
